## Key Implementation Decisions (this section)

- **Recovery store (Phase 7):** records keyed by workspace + canonical path +
  revision, strict record-name ownership in the private dir, typed refusals,
  age/count retention with a clamped maximum (a `u64::MAX` value would otherwise
  wrap negative and delete everything), bounded startup re-offer with a distinct
  document count.
- **Idle snapshot scheduling (Phase 7 Task 4):** dirty documents were never
  snapshotted while idle because the pass ran only on event iterations; fixed
  with `SnapshotThrottle::remaining` + `App::recovery_snapshot_wait` folded into
  `LoopWake::Timer`, with admission checks before `throttle.due`.
- **Acceptance-fixture sentinels (Ruling 26):** fixtures must use inert
  (impossible) sentinel inputs; a literal sentinel became a real command and
  produced a false failure that was initially misattributed to the code.
- **Read-only Git (Phase 8):** one whitelisted `status --porcelain=v2 -z
  --branch` invocation resolved through a **runtime** gate (release-enforced,
  proven with an injected write verb that is refused with no spawn),
  `--no-optional-locks`, `GIT_OPTIONAL_LOCKS=0`, `LC_ALL=C`, 4 MiB cap, 3 s
  timeout, process-group SIGKILL with `wait`.
- **Watcher feedback loop (Phase 8 Task 3):** `git status` opens working-tree
  directories, notify maps those opens to a generic change, and each refresh
  re-triggered the next (~25 invocations/second). Fixed with a 750 ms coalescing
  floor plus a bounded deferred wake (`git_deferred_refresh_at`, `loop_wait`,
  `wait_for_loop`) so a change dropped inside the window still converges with no
  further filesystem event.
- **Emulator selection (Phase 9 Task 1):** the in-repo `vte` parser extended in
  place, chosen because each fixture needs a neuter-to-red control and the
  brief's file allowlist excludes crate internals. `vt100` 0.15.2 (MIT, 11
  unique crates), `avt` 0.18.0 (Apache-2.0, 4), `alacritty_terminal` 0.26.0
  (Apache-2.0, 57 lock names, MSRV 1.85, edition 2024) were all built; D is the
  documented fallback if Task 2's nested full-screen fixture fails. No new
  dependencies; release size unchanged (0-byte delta, independently rebuilt).
- **Coverage basis discipline:** report the strict literal diff-inclusive basis
  first (hunks from `diff -U0` intersected with LCOV `DA:` lines), exclude test
  code by `#[cfg(test)]` **region** (not module name - `main.rs` has test
  modules interleaved before and after production code), and name any

## Learnings from This Section

### Patterns Discovered

- Run the **real binary** against a logging fake dependency to count invocations;
  unit tests cannot see self-sustaining loops where every step is individually
  correct.
- A test that recomposes production logic does not own it. Extract the
  production expression (`loop_wait`/`wait_for_loop`) so the test drives the real
  path; a structural source guard is justified only for the bypass class a unit
  test cannot reach.
- Coalescing must **defer**, not drop: record the deadline and let the existing
  bounded timer wake issue one follow-up per dropped window.
- Verify "pre-existing failure" claims by A/B (revert the guard, re-run) plus a
  screen dump before believing them.
- Guard against irreversibility at the boundary: clamp destructive parameters,
  require confirmation for broad destructive commands (`FileManagerTUI-9kk` open).

### Gotchas Encountered

- notify OPEN events + a tool that opens directories = feedback loop until a rate
  bound exists.
- Rust test modules may be interleaved anywhere in a file; exclude by
  `#[cfg(test)]` region, never by module name.
- Reindentation (wrapping a `match`) makes pre-existing lines look changed and
  uncovered; state the basis and name the lines.
- `.beads` ids were mis-cited twice; verify with `bd show` before recording.
